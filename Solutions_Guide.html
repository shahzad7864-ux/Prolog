## Start here
1. Extract the entire ZIP folder.
2. Use a SWI-Prolog installation for the `solution.pl` files. No Python packages are needed to run the practicals.
3. Open one practical folder and read `README.md`, or open `Solutions_Guide.html` in a browser for all solutions in one printable guide.

5. Load each practical in a **fresh Prolog session**. Independent exercises intentionally reuse predicate names, especially 7/8 and 9/10.
6. Exit with `halt.`. Prolog atoms start lowercase; variables start uppercase; each query ends in a period.

## Visual Prolog compatibility
The workbook explicitly names Visual Prolog for practicals 1 and 4 and refers to Domains, Predicates, Clauses and Goals. Those folders include `classic_visual_prolog.pro` using the legacy 5.x-style sections. Their failure-driven goal prints every answer and then fails intentionally. Modern Visual Prolog uses project/class structures and cannot directly compile these legacy files. The `solution.pl` editions use SWI-Prolog and cannot be passed unchanged to Visual Prolog. Confirm your lab's compiler version if Visual Prolog submission is mandatory.

## Data and output conventions
All sample facts, score thresholds, graphs and numerical objectives were chosen for these solutions because the workbook supplies tasks rather than datasets. Sample results are expected logical answers, not captured execution logs. Prolog may show different spacing or additional `true`/`false` prompts. Practical 10 is stochastic and deliberately does not invent exact measured outputs.

## Verification
No Prolog executable was available in the preparation environment; these programs were reviewed but not executed here. `verify.py` runs the supplied behavioral checks in separate SWI-Prolog processes when Python 3 and `swipl` are available. Run `python verify.py` from this extracted folder. It checks boundary cases, search costs, CSP counts and annealing invariants; it does not require annealing to reach the global optimum. Legacy Visual Prolog files require their own compiler and are not covered by that script.

## Assignment
Experiment 1: Write a basic Visual Prolog program to define a simple Knowledge Base of facts (e.g., student-course enrollment or a "likes" relationship database) to understand the core structure of Domains, Predicates, Clauses, and Goals.

02 · Implement arithmetic operations, Factorial, and Fibonacci Series using recursion

# Practical 2: Implement arithmetic operations, Factorial, and Fibonacci Series using recursion

## Assignment
Experiment 2: Implement a Prolog program to demonstrate basic arithmetic operations, finding the Factorial of a number, and generating the Fibonacci series.

## Aim and concept
Recursion reduces a problem to a smaller instance until a base case is reached. Factorial uses N! = N × (N−1)! and 0! = 1. Fibonacci uses F(0)=0, F(1)=1. Accumulators avoid recomputing earlier Fibonacci values.

## Algorithm
1. Evaluate arithmetic with is/2.
2. Guard division against zero.
3. Recursively multiply for factorial.
4. Carry the previous two terms for Fibonacci.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- arithmetic(10,3,S,D,P).
S = 13, D = 7, P = 30.
?- quotient(10,4,Q).
Q = 2.5.
?- quotient(10,0,_).
false.
?- factorial(5,F).
F = 120.
?- fibonacci(7,F).
F = 13.
?- fibonacci_series(8,L).
L = [0,1,1,2,3,5,8,13].
?- factorial(-1,_).
false.
```

## Result
The program computes arithmetic values, factorials and a series of N Fibonacci terms.

## Assumptions and limitations
N must be a bound nonnegative integer. Invalid arguments fail. These arithmetic predicates calculate forward; they do not solve for unknown inputs. Factorial uses linear recursion; Fibonacci runs in O(N) arithmetic steps.

Complete SWI-Prolog source

% Arithmetic predicates expect instantiated numbers.
arithmetic(A,B,Sum,Difference,Product) :-
    number(A), number(B), Sum is A+B, Difference is A-B, Product is A*B.
quotient(A,B,Q) :- number(A), number(B), B =\= 0, Q is A/B.
factorial(N,F) :- integer(N), N >= 0, fact(N,F).
fact(0,1).
fact(N,F) :- N > 0, M is N-1, fact(M,G), F is N*G.
fibonacci(N,F) :- integer(N), N >= 0, fib(N,0,1,F).
fib(0,A,_,A).
fib(N,A,B,F) :- N > 0, M is N-1, C is A+B, fib(M,B,C,F).
% N is the number of terms, starting with F(0)=0.
fibonacci_series(N,L) :- integer(N), N >= 0, series(N,0,1,L).
series(0,_,_,[]).
series(N,A,B,[A|T]) :- N > 0, M is N-1, C is A+B, series(M,B,C,T).

03 · Perform append, reverse, member search, and list length operations

# Practical 3: Perform append, reverse, member search, and list length operations

## Assignment
Experiment 3: Write a Prolog program to perform list manipulation operations (appending two lists, reversing a list, and searching for an element).

## Aim and concept
Lists consist of a head and tail, written [H|T]. Structural recursion processes one element at a time. The empty list is the base case. An accumulator makes reversal linear in list length.

## Algorithm
1. Append by copying heads from the first list.
2. Reverse by moving each head to an accumulator.
3. Match the head or search the tail for membership.
4. Add one per element for length.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- my_append([1,2],[3,4],R).
R = [1,2,3,4].
?- my_reverse([a,b,c],R).
R = [c,b,a].
?- my_member(b,[a,b,c]).
true.
?- my_member(z,[a,b,c]).
false.
?- my_length([a,b,c],N).
N = 3.
?- my_reverse([],R).
R = [].
```

## Result
Append, reverse, member search and list length are implemented without calling their built-in equivalents.

## Assumptions and limitations
Use finite proper lists. my_length/2 is intended for a supplied list, not generation from a length. Membership can return multiple proofs for repeated elements.

Complete SWI-Prolog source

my_append([],L,L).
my_append([H|T],L,[H|R]) :- my_append(T,L,R).
my_reverse(L,R) :- reverse_acc(L,[],R).
reverse_acc([],A,A).
reverse_acc([H|T],A,R) :- reverse_acc(T,[H|A],R).
my_member(X,[X|_]).
my_member(X,[_|T]) :- my_member(X,T).
my_length([],0).
my_length([_|T],N) :- my_length(T,M), N is M+1.

06 · Implement Breadth-First Search (BFS) to find the shortest path in a graph

# Practical 6: Implement Breadth-First Search (BFS) to find the shortest path in a graph

## Assignment
Experiment 6: Implement a graph traversal algorithm using Breadth-First Search (BFS) in Prolog to find the shortest path between two nodes.

## Aim and concept
BFS expands the earliest enqueued path first. On an unweighted graph it finds a path with the fewest edges. Nodes are marked seen when enqueued, preventing repeated expansion and cycles.

## Algorithm
1. Put the start path in a FIFO queue.
2. Remove the oldest path.
3. Return if its last node is the goal.
4. Enqueue paths extended to unseen neighbors.
5. Fail when the queue is empty.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- bfs(a,g,P).
P = [a,b,d,g].
?- bfs(a,a,P).
P = [a].
?- bfs(g,a,P).
false.
```

## Result
A shortest path from a to g has three edges. Cycles do not cause infinite traversal.

## Assumptions and limitations
Edges are directed and unweighted. For undirected graphs add reverse edges. The list-based queue is simple for teaching; repeated append and list membership make it slower than an optimized queue/set implementation.

Complete SWI-Prolog source

edge(a,b). edge(a,c). edge(b,d). edge(c,e).
edge(d,g). edge(e,g). edge(e,a).
node(a). node(b). node(c). node(d). node(e). node(g).
bfs(Start,Goal,Path) :- node(Start), node(Goal), queue([[Start]],Goal,[Start],Rev), reverse(Rev,Path).
queue([[Goal|T]|_],Goal,_,[Goal|T]) :- !.
queue([[N|T]|Rest],Goal,Seen,Path) :-
    findall(X,(edge(N,X), \+ memberchk(X,Seen)),Raw),
    sort(Raw,Children),
    findall([X,N|T],member(X,Children),NewPaths),
    append(Rest,NewPaths,Q), append(Seen,Children,Seen1),
    queue(Q,Goal,Seen1,Path).

07 · Implement Greedy Best-First Search using a heuristic function to find a path in a graph

# Practical 7: Implement Greedy Best-First Search using a heuristic function to find a path in a graph

## Assignment
Experiment 7: Implement Greedy Best-First Search in Prolog, using a heuristic function to guide node expansion toward the goal.

## Aim and concept
Greedy Best-First Search prioritizes the smallest heuristic h(n), ignoring accumulated cost when choosing what to expand. Cost is tracked only to report the resulting route.

## Algorithm
1. Add the start state with priority h(start).
2. Remove the lowest-priority state.
3. Stop at g, or expand unclosed successors.
4. Sort the frontier by heuristic and repeat.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- greedy(s,g,P,C).
P = [s,a,g], C = 10.
?- greedy(g,g,P,C).
P = [g], C = 0.
```

## Result
Greedy chooses a because h(a)=1 is lower than h(b)=3; it returns cost 10 although a cost-5 route exists.

## Assumptions and limitations
The heuristic is defined for goal g only. Greedy is not guaranteed optimal, even with an admissible heuristic. Edges and heuristic values are illustrative. Each node is expanded at most once; an empty frontier fails.

Complete SWI-Prolog source

arc(s,a,2). arc(s,b,1). arc(a,g,8). arc(b,c,2). arc(c,g,2).
h(s,4). h(a,1). h(b,3). h(c,2). h(g,0).

% Heuristics in this example are estimates to the fixed goal g.
greedy(Start,g,Path,Cost) :- h(Start,H),
    greedy_open([H-state(Start,[Start],0)],[],Rev,Cost), reverse(Rev,Path).
greedy_open([_-state(g,P,C)|_],_,P,C) :- !.
greedy_open([_-state(N,P,C)|Rest],Closed,Result,Cost) :-
    ( memberchk(N,Closed) -> greedy_open(Rest,Closed,Result,Cost)
    ; findall(H-state(X,[X|P],C1),
          (arc(N,X,W), \+ memberchk(X,[N|Closed]), C1 is C+W, h(X,H)),New),
      append(Rest,New,All), keysort(All,Sorted),
      greedy_open(Sorted,[N|Closed],Result,Cost)
    ).

08 · Implement the A* Search algorithm to find the optimal path using path cost and heuristic estimate

# Practical 8: Implement the A* Search algorithm to find the optimal path using path cost and heuristic estimate

## Assignment
Experiment 8: Implement the A* Search algorithm in Prolog, combining path cost (g) and heuristic estimate (h) to find the optimal path.

## Aim and concept
A* ranks states by f(n)=g(n)+h(n). It stores the cheapest discovered cost for each node, skips stale entries and reopens nodes when a cheaper route is discovered.

## Algorithm
1. Initialize the start with g=0.
2. Pop minimum f.
3. Discard stale entries.
4. Return when the goal is popped.
5. Relax outgoing edges, retaining only cost improvements.
6. Re-sort the frontier.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- astar(s,g,P,C).
P = [s,b,c,g], C = 5.
?- astar(g,g,P,C).
P = [g], C = 0.
```

## Result
A* finds cost 5 on the same graph where Greedy returns cost 10. The expansion sequence is s, a, b, c, g.

## Assumptions and limitations
The supplied heuristic is admissible and consistent for goal g, and edge costs are nonnegative. These conditions justify optimality here. h(s)=4 ≤ true cost 5; h(a)=1 ≤ 8; h(b)=3 = 3; h(c)=2 = 2. Do not reuse these heuristic values for a different goal.

Complete SWI-Prolog source

arc(s,a,2). arc(s,b,1). arc(a,g,8). arc(b,c,2). arc(c,g,2).
h(s,4). h(a,1). h(b,3). h(c,2). h(g,0).

astar(Start,g,Path,Cost) :- h(Start,H),
    astar_open([H-state(Start,[Start],0)],[Start-0],Rev,Cost), reverse(Rev,Path).
astar_open([_-state(N,P,G)|Rest],Best,Path,Cost) :-
    memberchk(N-Known,Best),
    ( G > Known -> astar_open(Rest,Best,Path,Cost)
    ; N == g -> Path=P, Cost=G
    ; findall(X-W,arc(N,X,W),Children),
      relax(Children,P,G,Rest,Best,Open1,Best1),
      keysort(Open1,Sorted), astar_open(Sorted,Best1,Path,Cost)
    ).
relax([],_,_,Open,Best,Open,Best).
relax([X-W|Xs],P,G,Open,Best,Final,FinalBest) :-
    G1 is G+W,
    ( memberchk(X-Old,Best), Old =< G1 -> Open1=Open, Best1=Best
    ; h(X,H), F is G1+H,
      Open1=[F-state(X,[X|P],G1)|Open],
      ( select(X-_,Best,Tail) -> Best1=[X-G1|Tail] ; Best1=[X-G1|Best] )
    ),
    relax(Xs,P,G,Open1,Best1,Final,FinalBest).

09 · Implement Hill Climbing for optimization problems

# Practical 9: Implement Hill Climbing for optimization problems

## Assignment
Experiment 9: Implement the Hill Climbing Algorithm to find the optimum solution for a numerical optimization problem.

## Aim and concept
Hill climbing moves to the best adjacent state only when its value is strictly better. This finite one-dimensional objective has a local maximum at x=2 and a global maximum at x=8.

## Algorithm
1. Start at a valid integer x.
2. Evaluate x−1 and x+1 within the domain.
3. Move to the highest-scoring neighbor if it improves the score.
4. Stop otherwise.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- hill_climb(0,X,V,T).
X = 2, V = 6, T = [0,1,2].
?- hill_climb(5,X,V,T).
X = 8, V = 12, T = [5,6,7,8].
```

## Result
From 0, hill climbing stops at the local maximum 2. Starting at 5 reaches the global maximum 8.

## Assumptions and limitations
The numeric objective is an explicitly tabulated function, not a real dataset. Strict improvement guarantees termination on this finite domain, but not global optimality. Ties choose the larger x due to term sorting.

Complete SWI-Prolog source

% Maximize this finite numerical objective over integer x in [0,10].
score(0,0). score(1,3). score(2,6). score(3,5). score(4,4).
score(5,5). score(6,7). score(7,9). score(8,12). score(9,10). score(10,8).
neighbor(X,Y) :- Y is X-1, Y >= 0.
neighbor(X,Y) :- Y is X+1, Y =< 10.
hill_climb(Start,Best,Value,Trace) :- integer(Start), score(Start,_), climb(Start,Best,Value,Trace).
climb(X,Best,Value,[X|Tail]) :-
    score(X,V), findall(S-Y,(neighbor(X,Y),score(Y,S)),Candidates),
    keysort(Candidates,Sorted), last(Sorted,NextValue-Next),
    ( NextValue > V -> climb(Next,Best,Value,Tail)
    ; Best=X, Value=V, Tail=[] ).

10 · Solve an optimization problem using Simulated Annealing to escape local optima

# Practical 10: Solve an optimization problem using Simulated Annealing to escape local optima

## Assignment
Experiment 10: Implement Simulated Annealing in Prolog and compare its ability to escape local optima against plain Hill Climbing.

## Aim and concept
Simulated annealing can accept a downhill move with probability exp((new−current)/T) for maximization. High temperature favors exploration; cooling reduces that probability. The best visited state is retained separately from the current state.

## Algorithm
1. Use the same landscape and start as Practical 9.
2. Pick a random neighbor.
3. Always accept an equal/better candidate; probabilistically accept a worse one.
4. Update the best visited state.
5. Cool by 0.99 and stop after 500 moves.
6. Compare five seeded runs with hill climbing.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- hill_climb(0,X,V,_).
X = 2, V = 6.
?- anneal(0,42,B,V,Trace), length(Trace,N).
% N = 501. B and V depend on the pseudo-random run.
% Global best, if reached: B = 8, V = 12.
?- compare.
% Prints hill-climbing result followed by five measured seeded runs.
```

## Result
Annealing can cross the valley at x=3 and x=4 to escape x=2. Use compare/0 to observe actual run outcomes; no stochastic success is guaranteed.

## Assumptions and limitations
Fixed seeds aid reproducibility within a runtime, but outputs may differ across versions. The trace includes rejected steps as repeated states. The reported result is the best visited point, not necessarily the final point. The finite budget does not prove global optimality.

Complete SWI-Prolog source

:- use_module(library(random)).


% Maximize this finite numerical objective over integer x in [0,10].
score(0,0). score(1,3). score(2,6). score(3,5). score(4,4).
score(5,5). score(6,7). score(7,9). score(8,12). score(9,10). score(10,8).
neighbor(X,Y) :- Y is X-1, Y >= 0.
neighbor(X,Y) :- Y is X+1, Y =< 10.
hill_climb(Start,Best,Value,Trace) :- integer(Start), score(Start,_), climb(Start,Best,Value,Trace).
climb(X,Best,Value,[X|Tail]) :-
    score(X,V), findall(S-Y,(neighbor(X,Y),score(Y,S)),Candidates),
    keysort(Candidates,Sorted), last(Sorted,NextValue-Next),
    ( NextValue > V -> climb(Next,Best,Value,Tail)
    ; Best=X, Value=V, Tail=[] ).

% Accept worse candidates with probability exp(delta / temperature).
anneal(Start,Seed,Best,Value,Trace) :-
    integer(Start), score(Start,V), integer(Seed), set_random(seed(Seed)),
    anneal_loop(500,10.0,Start,V,Start,V,Best,Value,Trace).
anneal_loop(0,_,X,V,B,BV,B,BV,[step(X,V)]) :- !.
anneal_loop(K,T,X,V,B,BV,Best,Value,[step(X,V)|Tail]) :-
    K > 0, findall(Y,neighbor(X,Y),Ys), random_member(Candidate,Ys),
    score(Candidate,CV), Delta is CV-V,
    ( Delta >= 0 -> NX=Candidate, NV=CV
    ; R is random_float,
      ( R < exp(Delta/T) -> NX=Candidate, NV=CV ; NX=X, NV=V ) ),
    ( NV > BV -> NB=NX, NBV=NV ; NB=B, NBV=BV ),
    K1 is K-1, T1 is max(0.001,T*0.99),
    anneal_loop(K1,T1,NX,NV,NB,NBV,Best,Value,Tail).
compare :-
    hill_climb(0,H,HV,_), format('Hill climbing: x=~w, value=~w~n',[H,HV]),
    forall(between(1,5,Seed),
       (anneal(0,Seed,B,V,_), format('Annealing seed ~w: x=~w, value=~w~n',[Seed,B,V]))).

12 · Solve the N-Queens problem using backtracking to satisfy CSP constraints

# Practical 12: Solve the N-Queens problem using backtracking to satisfy CSP constraints

## Assignment
Experiment 12: Implement the N-Queens problem in Prolog using backtracking, ensuring no two queens attack each other.

## Aim and concept
Place one queen per row. Selecting from unused columns prevents column conflicts. A pair of queens attacks diagonally when the absolute column difference equals their row distance.

## Algorithm
1. Create available columns 1 through N.
2. Pick an unused column for the next row.
3. Check its diagonals against previous rows.
4. Recurse or backtrack until all rows are assigned.

## Run
Open SWI-Prolog in this folder and enter `['solution.pl'].` Then run the queries below. The `?-` is the console prompt; do not type it twice. Press `;` for more answers or Enter to stop.

## Sample queries and expected results
```prolog
?- n_queens(4,Q).
Q = [2,4,1,3] ; Q = [3,1,4,2].
?- n_queens(2,_).
false.
?- findall(Q,n_queens(8,Q),Qs), length(Qs,Count).
Count = 92.
?- once(n_queens(4,Q)), print_board(Q).
. Q . .
. . . Q
Q . . .
. . Q .
Q = [2,4,1,3].
```

## Result
Backtracking finds valid N-Queens arrangements; N=4 has two solutions and N=8 has 92 when rotations/reflections are counted separately.

## Assumptions and limitations
N must be a bound integer ≥1. N=2 and N=3 have no solutions. The basic backtracking method becomes expensive for large N. The list contains columns in increasing row order.

Complete SWI-Prolog source

% Row position in the list is the row number; its value is the column.
n_queens(N,Columns) :- integer(N), N >= 1,
    numlist(1,N,Available), place(Available,[],Columns).
place([],_,[]).
place(Available,Previous,[C|Rest]) :-
    select(C,Available,Remaining),
    safe(C,Previous,1),
    place(Remaining,[C|Previous],Rest).
safe(_,[],_).
safe(C,[P|Ps],Distance) :-
    abs(C-P) =\= Distance,
    Next is Distance+1, safe(C,Ps,Next).
print_board(Columns) :- length(Columns,N),
    forall(member(C,Columns),
       (forall(between(1,N,J),(J =:= C -> write('Q ') ; write('. '))),nl)).
